# Зрение: две работы, две папки

Над пространственным зрением независимо работали два человека с двумя ИИ-агентами,
и 05.08.2026 работы столкнулись: в `main` и в ветке `vision-spatial-b` оказались
**два разных файла `tools/visual_field_map.py`** — одно имя, одна задача, разные
реализации. Слить их нельзя, выбрать одну — значит выбросить независимую проверку.

Поэтому работы разведены по папкам. Ни один файл не удалён.

```
vision/
  README.md          <- этот файл: правила для обоих
  gosha/             <- ChasoniCK: карта по цепочке синапсов, без flyvis
  fedor/             <- fedor655: гибрид с обученным flyvis
```

Общий код (контур, тело, запись, просмотр) остался в корне и в `tools/` — он
принадлежит обоим.

## Правила, обязательные для обоих агентов

**1. Свою папку менять можно, чужую — нельзя.** Ни переименований, ни «заодно
поправил», ни исправления чужих опечаток. Если в чужой папке настоящая ошибка —
написать об этом в своём отчёте, а не чинить.

**2. Общие файлы менять можно, но осторожно.** Их список:

| Файл | Что делает |
|---|---|
| `closed_loop_vision.py` | замкнутый контур: глаза → проекционные → нисходящие → походка |
| `flyreplay.py` | сцена `PillarWorld`, запись траектории, вид с глаз |
| `replay_view.py`, `replay_render.py` | интерактивный просмотр и рендер mp4 |
| `flypaths.py` | пути, `MUJOCO_GL` |
| `tools/*.py` | инструменты, написанные до разделения |
| `PROJECT_LOG.md`, `HANDOFF.md`, `ROADMAP.md` | журнал и передача |

Перед правкой общего файла — `git fetch`. Правка минимальная и обратно
совместимая: новые параметры только со значениями по умолчанию, при которых
поведение прежнее. В сообщении коммита сказать, зачем это понадобилось твоей
стороне.

**3. Работать в своей ветке, в `main` не пушить напрямую.** Перед push —
`git fetch` и `rebase`, не `force`. Ветки: `vision-spatial-b` (Гоша) и то, что
использует Федя.

**4. `output/` общий, имена не пересекаются — так и держать.** Проверено на
05.08.2026: пересечений нет. Если добавляешь новый файл результата, сначала
`grep -r 'out("' vision/` — не занято ли имя.

**5. Один кэш действительно общий.** `output/dn_population_cache.npz` — популяция
латерализованных нисходящих, отобранная стимуляцией. **Пишет его только
`closed_loop_vision.py`.** `vision/fedor/dn_population_seam.py` его читает для
сравнения и не перезаписывает. Не менять это без согласования: молча подменённый
кэш изменит поведение контура, и это не будет видно в дифе.

## Что где

### `vision/gosha/` — карта по цепочке синапсов

Ветка `vision-spatial-b`. Новых зависимостей не добавляет.

| Файл | Что делает |
|---|---|
| `visual_field_map.py` | оси листа сетчатки по анатомическим реперам, положение нейрона = взвешенное среднее положений его входов по цепочке сетчатка → ламина → медулла → проекционные, разбивка на 4 полосы, split-half контроль, `self_check()` |
| `zone_discrimination.py` | шлагбаум: различает ли выход мозга произвольные подмножества зрительного входа |
| `replicate_spatial.py` | серия этапа 2: 5 сцен × 2 режима входа × 8 seed |
| `test_spatial.py` | единственная запускаемая проверка карты и подачи |

```bash
.venv/bin/python vision/gosha/visual_field_map.py     # построить карту и проверить её
.venv/bin/python vision/gosha/test_spatial.py         # проверка карты и подачи, секунды
.venv/bin/python vision/gosha/zone_discrimination.py  # этап 0, около 20 минут
```

Ключевые числа: шлагбаум пройден (внутригрупповая корреляция откликов 0.949 против
межгрупповой −0.320, t = −59.4); ось карты — азимут (split-half 0.947 и 0.915 при
пороге 0.5, перестановочный контроль обрушивает до 0.018 и 0.012).

### `vision/fedor/` — гибрид с обученным flyvis

**Требует `flyvis`**, которого нет в базовом окружении. На машине без него эти
файлы импортируются, но не работают — это нормально, а не поломка.

Разложение 721 колонки flyvis по нейронам коннектома, стык по зрительным
проекционным, декодер команды по нисходящим. Подробности — в `PROJECT_LOG.md`,
разделы «Шаги 1.2 и проверка обученного flyvis», «Шаг 1.3», «Горлышко».

## Результат, к которому обе стороны пришли независимо

Это главное, ради чего обе работы стоит держать рядом.

| | Гибрид с flyvis (Федя) | Цепочка синапсов (Гоша) |
|---|---|---|
| Пространственная информация доходит до зрительных проекционных | да, **12–17σ** на лобуле | да, Жаккар множеств 0.703 |
| Доходит до нисходящих / до поведения | **нет**, 1.1σ и ниже | **нет**, \|t\| ≤ 1.80 |

Две несвязанные методики упёрлись в одну стену в одном месте: горлышко из 1299
нисходящих нейронов. Каждая сторона закрывает оговорку другой:

- Федя мерил **мгновенным снимком** на стоящей мухе и честно оговорил, что слабый
  пооконный сигнал мог бы дать поведение накоплением. У Гоши муха шла 100 циклов
  со сглаживанием команды 150 мс, то есть именно накоплением, — разницы между
  пространственным и скалярным входом всё равно нет.
- У Гоши сцены основной пары разъехались по суммарной яркости в 8.2 раза, поэтому
  его опыт не мог отделить вклад карты от вклада яркости. У Феди сцены
  симметричные, а ось декодера искалась по данным с перекрёстной проверкой — и всё
  равно ноль на нисходящих.

Ни одна из сторон в одиночку этот вывод не держит. Вместе — держат.

## Что произошло при разделении (для агента Феди)

Файлы Феди переехали из `tools/` в `vision/fedor/` **без изменения содержания**,
кроме одной строки в каждом:

```python
sys.path.insert(0, str(Path(__file__).resolve().parents[1]))   # было
sys.path.insert(0, str(Path(__file__).resolve().parents[2]))   # стало
```

Глубина до корня репозитория выросла на уровень. Больше ничего не тронуто:
импорты, логика, имена файлов результатов — как были.

Проверено на этой машине: из семи файлов, не требующих `flyvis`, шесть
импортируются штатно, седьмой (`visual_field_reference_check.py`) падает с
`FileNotFoundError` на `output/visual_field_map.csv` — этого файла просто нет на
машине, он git-ignored и создаётся конвейером Феди. Путь при этом резолвится в
корень репозитория верно, то есть переезд ни при чём.

**Девять файлов, требующих `flyvis`, запуском не проверялись** — зависимости нет.
Их синтаксис в порядке, путь до корня исправлен так же. Проверить их работу должна
сторона Феди, и это стоит сделать первым же прогоном.

Старые пути в `docs/superpowers/specs/` и `docs/superpowers/plans/` намеренно
**не** переписаны: это исторические документы, описывающие состояние на момент
написания. Проект хранит записи как были — на этом стоит весь журнал.
